# B0 Builder Policy

Status: `LOCAL OPERATING POLICY / OWNER-LED / SPEED-FIRST`

Date: `2026-10-26`

## Purpose

Build the smallest useful thing, finish it cleanly and return it to its source.
This policy supports one Human Owner. It should reduce coordination, not create
administration.

## Working rules

1. **One active cut.** Finish, hold or close the current cut before opening a
   competing one.
2. **Start from the real goal.** Record the intended use and visible finish in
   one sentence. Do not expand the task merely because related material exists.
3. **Reuse before creating.** Search the existing component, page, identity and
   source first. Extend the owning source instead of making a parallel copy.
4. **Build at the source.** B0 points to work; the owning repository keeps code,
   semantics, evidence and history.
5. **Test in proportion.** Run the smallest checks that can catch a meaningful
   failure. Shared navigation, manifests and release paths require their full
   existing validators.
6. **Return the result.** A finished cut states what changed, what passed, what
   remains open and where authority returns.
7. **Choice before depth.** Navigation shows the current route and only opens
   the depth a person deliberately chooses. Every opened room, panel or detour
   includes a visible close or Return path to the last orientation point.
8. **Separate build from judgment.** Working software is not automatically a
   scientific Finding, product validation or publication approval.
9. **Keep one current version.** Use Git for ordinary history. Preserve a
   separate archive copy only when it has lasting provenance value; mark it
   `ARCHIVED` or `SUPERSEDED` and point to the current successor.
10. **One writer on shared files.** Parallel chats may inspect or work on
   disjoint files. Navigation, manifests, binders and generated projections
   have one active editor until validation and return are complete.
11. **Local first.** Work and validate in the canonical local checkout. Commit
    a coherent checkpoint. Push, deployment and publication remain separate
    Owner decisions.
12. **Website custody stays explicit.** `nexah.de`, A0, `nexahedron.com` and
    `www.scarabaeus1033.net` retain separate canonical repositories. A0 may
    stage and connect their views; B0 may route work and classify legacy pages.
    Neither becomes a second website master. Generated bundles are rebuilt
    from their declared source and manifest, never hand-edited. Commit only an
    exact reviewed path set in the owning repository; push and deploy require
    their own Owner gates.

## Minimum build card

Before work, only these fields are needed:

- goal;
- owning source;
- active cut;
- finish condition;
- relevant check;
- return destination.
- for website work: public channel, canonical repository and whether the
  touched path is `SOURCE`, `GENERATED_PROJECTION` or `LEGACY_DISPOSITION`.

If one is unclear, make the narrowest reversible assumption and keep moving.
Ask the Owner only when the choice changes meaning, authority, public scope or
destroys material.

## Done

A Builder cut is done when:

- the intended use works;
- the relevant check passes;
- opened depth can be closed and returns to a visible orientation point;
- the current source and links are unambiguous;
- displaced versions are classified rather than left competing;
- the result has returned to Mission Control, or to the Science Desk when it
  affects scientific interpretation.

`DONE` does not mean published. `HOLD` is a valid closeout when the missing
input or decision is named.

## Compact loop

```text
GOAL → SOURCE → SMALL CUT → CHECK → RETURN → CLOSE
```

No new Builder identity, scientific claim, Study, release or publication is
created by this policy.
