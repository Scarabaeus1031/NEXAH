# Final Recommendation

## Decision

**D — NEXAH needs a structured, repository-level evidence navigation layer.**

It should be called **NEXAH Evidence Atlas**.

Alternatives, in descending preference:

1. Evidence Ledger
2. Findings Atlas

“Discovery Atlas” is not recommended as the canonical name because it can
suggest novelty and positive success. The repository needs equal visibility for
exact constructions, architectural validations, supported findings, negative
results, limitations, open hypotheses, historical explorations, and blockers.

## What the desk should contain

One conservative claim register with:

- stable IDs;
- one-sentence bounded claims;
- controlled status and scope;
- evidence type and reproducibility;
- one authoritative source;
- supporting and limiting sources;
- prohibited implications and open questions.

## What it must exclude

It must not define Architecture, OLS, ORION, Kernel, Processor, application, or
Library authority. It must not copy evidence, become a result database, infer
mathematics from visuals, resolve open hypotheses, hide negative results, or
promote historical language.

## Where it should live

`docs/evidence/README.md`

This makes it cross-system documentation. It should not live under Research,
Architecture, Library, or Validation because each of those has narrower
authority.

## Smallest safe implementation

Create one Markdown page from this review's 28 entries and add a few inbound
links. Do not create claim subpages, JSON, a registry, or automation in the
first iteration.

## Timing

Implementation may happen **next**, as a separate approved documentation task,
provided the three blocked evidence chains remain visibly blocked or their
authoritative repository sources are first restored. The missing sources do not
prevent an atlas; they prevent those particular claims from being represented
as established results.

## Next concrete task

Create the single-page NEXAH Evidence Atlas from the reviewed register, verify
all source links, and add only root/Research/Validation/Applications/docs entry
links. Do not edit source claims or evidence bundles.

## Final answer

NEXAH does need a central desk where important results converge, but only as a
map. The evidence must remain where it was produced.
