# Current Narrative

This document describes the current repository narrative without evaluating it.

## Repository front door

The root README introduces NEXAH as an evidence-bound orientation ecosystem. It presents six coordinated subsystems, their authority boundaries, current state, one executable entry, evidence limits, and a compact directory map. Visitors choose an entry by purpose.

## Research

Research is the evidence layer. Its current portal emphasizes complex dynamical systems, structured fields, transition geometry, JANUS, validation, findings, applied cases, and theoretical extensions. It identifies the work as active research rather than a finalized theory.

## Orientation Language

Orientation Language is the published semantic authority. It owns the canonical OLS 1.0 release, declarations, contracts, profiles, derivations, conformance rules, registries, versioning, and specification governance. Research and applications may inform or realize it but do not define released semantics.

## Implementations

The installable `nexah/` package and reference implementation areas execute declared structures and produce inspectable behavior. Implementation does not become semantic authority, and conformance is not assumed.

## Applications

Applications is where NEXAH methods meet concrete systems. Its README presents runnable tools, reference systems, applied research programs, adapters, prototypes, conceptual models, power systems, network orientation, dynamical systems, demonstrations, and navigation experiments.

## Living Library

The Library is the human-facing visual and editorial layer. Are.na remains authoritative for visual publication and sequence; the Registry preserves stable identity and curated relationships; the Kernel may derive explainable orientation without replacing human authority.

## Editorial Operating System

The Editorial Operating System coordinates editorial knowledge, reader context, policies, human review, controlled execution, verification, and reproducible explanation. The Living Library is its first reference implementation.

## Architecture

Architecture explains relationships, system state, methods, implementation frontiers, historical lineages, and the boundaries between the six responsibilities. It is a relationship and status layer rather than a seventh subsystem.

## Repository Map

The Repository Map translates the six-subsystem architecture into directory-level navigation. It provides paths for general visitors, specification readers, researchers, developers, application evaluators, Library readers, editorial contributors, and experimental explorers.
