# Edge Comparison

An edge is a directional, scoped, evidence-bearing transition claim. Matching endpoints are insufficient to establish the same edge.

## Edge anatomy

Every comparable edge should expose:

- source node and target node;
- direction;
- relation statement;
- orientation role or purpose;
- support class;
- evidence location;
- scope and scale;
- uncertainty;
- unsupported implications;
- local version and reviewer.

## Comparison tests

| Test | Question | Possible result |
|---|---|---|
| Endpoint identity | Are both endpoint pairs independently identity-matched? | yes / partial / no / unresolved |
| Direction | Do both edges point between corresponding endpoints in the same direction? | same / reverse / mixed / unresolved |
| Relation semantics | Do the predicates make the same scoped claim? | equivalent / compatible / different / unresolved |
| Support | Are support classes defined alike and backed by comparable evidence? | aligned / unequal / incomparable |
| Role | Does the edge serve the same orientational function? | same / different / absent |
| Scope | Do domain, time, scale, and context boundaries align? | same / overlapping / disjoint / unresolved |
| Unsupported implications | Do both records reject the same overreadings? | aligned / different / missing |

## When is an edge the “same”?

Only when corresponding endpoints have established scoped identity, direction matches, relation semantics are equivalent within aligned scope, and evidence supports that equivalence. Even then, the result is `edge_correspondence`, not a merged edge.

If one neighborhood records A → B and another B → A, those are two directional claims. They may be reciprocal, contradictory, complementary, or incomparable. The visual appearance of a two-way connection settles nothing.

## Evidence boundary

The stronger edge cannot upgrade the weaker edge. Comparison may report unequal support; it may not average, transfer, or launder support across neighborhoods.
