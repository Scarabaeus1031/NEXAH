# Action Extraction Protocol

## Required distinction

An artifact is a stored output. An action is something visibly done or explicitly instructed within or between outputs. One artifact may contain several actions; one action may appear in several artifacts.

For example, a Reflection is an artifact. In the reviewed corpus its contents may perform actions such as separating source support from editorial interpretation, recording unanswered questions, classifying candidate bridges, and declaring limits. Those actions are admitted only where exact files show them.

## Admission criteria

A candidate action is admitted only when:

1. it is visibly performed or explicitly instructed;
2. its input and output can be described;
3. at least one exact artifact reference exists;
4. it can be stated without a theory of cognition;
5. it is distinguishable from a filename or heading;
6. its wording does not imply universality;
7. missing or contrary cases are recorded.

## Evidence classes

- **explicitly instructed** — a governing artifact directs the act;
- **explicitly performed** — the record visibly carries it out;
- **reconstructed from before/after artifacts** — the action is needed to describe a visible change, but not stated contemporaneously;
- **reported retrospectively** — a later report says the act occurred;
- **template-imposed** — recurrence follows a shared required structure;
- **uncertain** — evidence cannot distinguish action, artifact effect, or analyst interpretation.

## Recurrence classes

- present in all three pilots;
- present in two pilots;
- present in one pilot;
- comparison-only;
- study-only;
- template recurrence;
- chronologically introduced;
- insufficiently comparable.

## Provisional indexing categories

Source handling; observation; separation; representation; comparison; relation handling; navigation; explanation; evidence control; rejection; uncertainty; reflection; stopping; verification; meta-evaluation.

These categories help locate actions. They are not stages, Operators, a complete taxonomy, or canonical architecture.

## Extraction procedure

1. Fix the pre-study file manifest and hashes.
2. Read artifact instructions and performed records separately.
3. Phrase candidate actions as plain verbs with bounded objects.
4. Record input, output, evidence class, exact references, recurrence, absences, and prohibited inference.
5. Test whether recurrence comes from the template, chronology, source, or analyst.
6. Map actions to sequences and dependencies without treating time as necessity.
7. Test each candidate against failure pressure and counterexamples.
8. Retain uncertainty and negative findings.

## Non-admission rules

A filename alone, a prompt suggestion, a repeated noun, a biological motif, a metaphor, a visual symbol, or a plausible cognitive act is insufficient. No action is admitted merely because the execution prompt lists it.
